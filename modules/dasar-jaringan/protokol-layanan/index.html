MATERI 01

Protokol dan Layanan Jaringan Dasar

Pelajari DNS, DHCP, HTTP/HTTPS, port layanan, dan alur komunikasi melalui simulasi serta game interaktif.

Tujuan Pembelajaran

  • Membedakan DHCP, DNS, HTTP, HTTPS, serta peran port transport.
  • Menjelaskan alur pencarian nama dan akses web.
  • Mencocokkan layanan dengan port konvensional dan batas penggunaannya.

Mengenal Protokol dan Layanan

Protokol menetapkan aturan komunikasi, sedangkan layanan menyediakan fungsi yang digunakan klien. Satu layanan dapat bergantung pada beberapa protokol. Membuka situs dengan nama domain biasanya melibatkan konfigurasi IP, pencarian DNS, transport, dan komunikasi web.

Konfigurasi

DHCP membantu memberi konfigurasi IP.

Penamaan

DNS mencari informasi melalui record.

Akses web

HTTP bertukar pesan web; HTTPS melindunginya dengan TLS.

Contoh: nama situs gagal tetapi IP dapat diakses. Periksa pencarian DNS sebelum mengubah seluruh jaringan.

DHCP dan Konfigurasi Otomatis

DHCPv4 dapat memberikan alamat, subnet mask, gateway, DNS, dan masa sewa. Alur awal yang umum adalah Discover → Offer → Request → Acknowledge (DORA), menggunakan UDP server 67 dan klien 68. Jika server berada di subnet lain, diperlukan rancangan relay yang sesuai.

Alamat yang berhasil diperoleh belum menjamin semua opsi benar. Periksa scope, sewa, gateway, dan resolver. Bandingkan konfigurasi klien dengan rencana alamat; hindari alamat statis bertabrakan dengan pool DHCP.

DNS dan Record

DNS menyediakan pencarian informasi nama. Record A berisi alamat IPv4, AAAA alamat IPv6, CNAME alias, dan MX tujuan layanan surat. Resolver dapat memakai cache sesuai TTL; tidak semua pencarian langsung menuju server otoritatif.

DNS konvensional memakai UDP atau TCP port 53; DNS tidak selalu hanya UDP. Gunakan alat kueri seperti nslookup untuk melihat jawaban dan server yang digunakan. Respons ping terhadap IP tidak membuktikan resolver DNS berfungsi.

HTTP, HTTPS, dan TLS

HTTP menggunakan pola permintaan dan respons; HTTPS mengamankan komunikasi HTTP dengan TLS. Browser memeriksa identitas server melalui sertifikat, lalu membentuk kanal terlindungi sesuai protokol yang digunakan. HTTP konvensional menggunakan TCP 80; HTTPS lazim menggunakan TCP 443, sementara HTTP/3 menggunakan QUIC melalui UDP.

HTTPS melindungi komunikasi selama perjalanan dan membantu autentikasi server. Itu tidak otomatis menjamin seluruh isi situs dapat dipercaya atau perangkat pengguna bebas masalah.
